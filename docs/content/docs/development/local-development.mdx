# Local Development

The main application lives in `web/`. Accounts, canvases, assets, and settings persist through Supabase, and the browser sends AI requests directly to the user's configured endpoints; enable the local forwarding proxy when CORS blocks them.

## 0. Prepare Supabase

Create `web/.env.local` (see `web/.env.example`); without it you cannot sign in and settings cannot be saved:

```text
VITE_SUPABASE_URL=<your Supabase Project URL>
VITE_SUPABASE_ANON_KEY=<your Supabase anon key>
```

For migrations and Edge Function deployment, see [Quick Start](/docs/overview/quick-start).

## Start the frontend

```bash
cd web
bun install
bun run dev
```

Open `http://localhost:3000`, then add your provider (`Base URL`, `API Key`, and model names) in the config page (`/config`). API keys are stored encrypted by the `channel-secrets` Edge Function. Prompt sources and WebDAV are also accessed directly by the browser.

## Start the documentation site

```bash
cd docs
bun run dev
```

Common locations:

- Canvas, pages, and interactions: `web/`
- Prompt data and the managed table access: `web/src/services/api/prompts.ts`
- Cloud persistence: `web/src/lib/supabase-storage.ts` and `web/src/services/supabase.ts`
- Documentation content: `docs/content/docs/`
