# Docker Deployment

The main application image is a Vite static frontend served by nginx; runtime configuration is generated from environment variables at container startup.

## Deployment

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
SUPABASE_URL=<your Supabase Project URL> \
SUPABASE_ANON_KEY=<your Supabase anon key> \
docker compose up -d --build
```

`docker-compose.yml` builds the local image `infinite-canvas:local` from the current source and requires `SUPABASE_URL` and `SUPABASE_ANON_KEY` (startup fails without them). Open `http://localhost:3000`.

Alternatively build the image yourself and run it directly:

```bash
docker build -t infinite-canvas .
docker run -d -p 3000:3000 \
  -e SUPABASE_URL=<your Supabase Project URL> \
  -e SUPABASE_ANON_KEY=<your Supabase anon key> \
  infinite-canvas
```

## Runtime environment variables

The container entrypoint generates runtime configuration from these variables, so no image rebuild is needed:

| Variable | Required | Description |
| --- | --- | --- |
| `SUPABASE_URL` | Yes | Supabase Project URL |
| `SUPABASE_ANON_KEY` | Yes | Supabase anon key (publishable key) |
| `ANALYTICS_GA4_ID` | No | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | No | Baidu site ID, the hash after `hm.js?` |

For Supabase migrations and Edge Function deployment, see [Quick Start](/docs/overview/quick-start).

## Data

Canvas projects, assets, preferences, and provider API keys are stored in Supabase per account (the `user_state` table and per-user Storage directories). The application container itself is stateless and needs no data volume.

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## Optional analytics

No analytics are enabled by default: without `ANALYTICS_GA4_ID` / `ANALYTICS_BAIDU_ID` the pages load no tracking scripts and send no external requests. Each provider has its own variable and they can be enabled together. Only GA4 and Baidu Analytics are supported; both accept only IDs, and script URLs are fixed by the code.

```yaml
services:
  app:
    # ... same SUPABASE configuration as above ...
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

Or add `-e ANALYTICS_GA4_ID=...` to `docker run`.

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
